# HackerNews — протокол поиска для агента

## MCP-инструменты

Namespace: `mcp__plugin_jadlis-research_hn__*`

| Инструмент | Назначение |
|---|---|
| `browse_stories` | Просмотр постов по категории (top/new/best/ask/show/job) |
| `search_hn` | Полнотекстовый поиск по всему HN (Algolia) |
| `get_story_details` | Пост с полным деревом комментариев |
| `user_analysis` | Профиль и активность пользователя |

## Ограничения обёртки hn-mcp@1.0.0 (сверено 2026-08-06)

- **`sortBy` — no-op.** Параметр объявлен в zod-схеме, но в Algolia не уходит; endpoint всегда
  `/search` (релевантностный), строки `search_by_date` в дистрибутиве нет. Не передавать —
  он создаёт ложную уверенность в свежести выдачи.
- **Кэш 10 минут, ключ — только `query`.** `tags`, `limit`, `dateRange` в ключ НЕ входят
  (`String(options)` → `"[object Object]"`). Два вызова с одинаковой строкой `query` внутри окна
  → второй молча вернёт ответ первого, без ошибки и без признаков подмены. Отсюда:
  варьировать формулировки между слоями; проверять поле `type` в хитах на соответствие
  запрошенному `tags`; при совпадении `query` считать ответ кэшем, а не свежими данными.
- **`numericFilters` не передавать.** Публичной ручки нет, zod срезает неизвестные ключи молча:
  ошибки не будет, фильтра тоже. Порог по `points` — постфильтром на своей стороне.
- **Свежесть — только `dateRange`.** Фильтр по окну реален, но порядок внутри окна остаётся
  релевантностным: брать больший `limit` и сортировать по `created_at` у себя.
- **`browse_stories type:"job"`** отдаёт одиночные вакансии YC-компаний (score 1, 0 комментариев),
  а не мегатред «Who is hiring» — для ресерча бесполезен.

## DEEP-DIVE Protocol

### Layer 1 — Поиск (3 вызова)

> **Критично: у трёх вызовов ДОЛЖНЫ быть разные формулировки `query`.** Ключ кэша hn-mcp
> состоит только из строки `query` (TTL 10 мин), `tags`/`limit`/`dateRange` игнорируются —
> при повторе той же строки второй и третий вызовы молча вернут результат первого, и слой
> исчезнет незамеченным. Контроль: поле `type` в хитах должно соответствовать `tags`.

1. **По stories** — базовая формулировка темы:
```json
search_hn({
  "query": "<ТЕМА>",
  "tags": "story",
  "dateRange": "pastYear",
  "limit": 30
})
```

2. **По комментариям** (для мнений) — формулировка №2, с оценочной лексикой
(`"<ТЕМА> опыт проблемы"`, `"<ТЕМА> vs альтернативы"`), НЕ строка из шага 1:
```json
search_hn({
  "query": "<ТЕМА + оценочный аспект>",
  "tags": "comment",
  "dateRange": "pastYear",
  "limit": 20
})
```

3. **Канонический проход** — БЕЗ dateRange, ловит мегатреды старше года
(проверено A/B-бенчмарком 2026-06: даёт треды-первоисточники без роста стоимости).
Формулировка №3 — синоним/смежный термин, НЕ строки из шагов 1–2:
```json
search_hn({
  "query": "<ТЕМА, синоним или смежный термин>",
  "tags": "story",
  "limit": 20
})
```

`sortBy` — no-op в hn-mcp@1.0.0, порядок всегда релевантностный: для свежего среза сужай
`dateRange` и сортируй хиты по `created_at` на своей стороне.

### Layer 2 — Контекст (0-1 вызов)

Если тема связана с Ask HN или текущими трендами:
```json
browse_stories({ "type": "ask", "limit": 30 })
```

Для продуктовых тем (демо, запуски, инструменты) — вместо `ask`:
```json
browse_stories({ "type": "show", "limit": 30 })
```
Лента Show HN общая, не тематическая — фильтровать по теме вручную. `type: "job"`
в протоколе не использовать (см. ограничения выше).

### Layer 3 — Глубокие комментарии (5-7 вызовов)

`get_story_details` для **топ 5-7 постов** из ОБЪЕДИНЕНИЯ всех трёх поисков Layer 1:

Критерии выбора:
1. `num_comments` >= 20
2. Высокий `score`/`points`
3. Максимальная релевантность запросу
4. Баланс: и свежие треды, и канонические (из прохода без dateRange)

```json
get_story_details({
  "id": "<story_id>",
  "maxComments": 30,
  "commentDepth": 5
})
```

### Layer 4 — Контраргументы (2-3 вызова)

После формирования ключевых тезисов — поиск опровержений:

1. `search_hn` с инвертированным запросом:
```json
search_hn({
  "query": "<инвертированный запрос: criticism/problems/alternatives>",
  "tags": "story",
  "dateRange": "pastYear",
  "limit": 15
})
```

2. `get_story_details` для топ 1-2 постов с контраргументами:
```json
get_story_details({
  "id": "<story_id>",
  "maxComments": 15,
  "commentDepth": 5
})
```

В выходном файле — отдельная секция:
```
## Контраргументы (найдены на HackerNews)
- [{prefix}N] {контраргумент} — {URL}
```

### Layer 5 — Эксперты (опционально)

`user_analysis` рабочий (сверено 2026-08-06). Условие вызова: ник встретился ≥2 раз
в комментариях Layer 3 И его тезис попал в claim.
```json
user_analysis({ "username": "<expert>", "submissionLimit": 5 })
```

Цена: 1 HTTP-запрос на каждый айтем (`submissionLimit: 10` = 11 запросов через
rate-limiter) → держать 5–10, не 15. Отдаёт `karma`, `created_ago`, `about` и полный
текст последних реплик (у активных комментаторов это в основном комментарии, `type: "comment"`).

## Правила цитирования (guardrails канонического прохода)

- У каждой цитаты указывай метаданные вовлечённости треда: score и число комментариев.
- Тред старше года → явная пометка «канонический, {год}» + проверь, не устарел ли тезис
  (если тезис load-bearing — быстрая сверка в Layer 4).
- Не более 3 цитат с одного треда — иначе выборка схлопывается в один источник.
