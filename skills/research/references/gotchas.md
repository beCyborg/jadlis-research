# Gotchas — run failures and their fixes

Failure modes observed on real runs. Format: anchor + what to do.

**Analyst dies on the session limit — the channel work is NOT lost.** 2026-08-12, two parallel full-research runs: the analyst on the Fable bridge failed with «You've hit your session limit», the workflow crashed whole (`null is not an object (report.reportPath)`), but all channel files and the verification were already cached. Fix: wait for the 5-hour window to reset (the time is in the error text) → `Workflow({scriptPath, resumeFromRunId})` with THE SAME args — only the analyst re-runs (~10–15 min), channels return from cache instantly.

**Check `draft.md` (`report.md` in runs before 2.5.1) in the workDir BEFORE resuming.** The analyst writes write-first, so the report can already be complete despite `is_error:true` in `_fable-analyst-out.json` (it died on the final structured return). Complete = frontmatter + methodology at the tail; the 2026-08-12 pair: FR-2 report 55 KB / 10 min / 44k output tokens — complete, take it into the vault as is; FR-1 611 output tokens in 8.6 s — empty, resume needed.

**Per-claim verification drops most channel claims — never write conclusions before the ledger.** Paired run 2026-08-13/14: RU 1 confirmed of 8, EN 3 of 8, **12–13 of 16 dropped**. What fell was load-bearing: «the $300–2000 band is empty» (it is populated by productized platforms, credibility 4), Kwork escrow payments as demand evidence, the price anchor «Wynter from $1 599» (a credit-recalculation example from the FAQ; the real entry is $99), the fake-door precedent «713 visits → 0 sales» (channels glued together), four RU quotes «the neural net made the data up» (none verified). The Grok channel generated a plausible non-existent pain quote — caught by the verifier, and five more verbatim LLM-channel quotes without a checkable URL went with it. Channel `.md` files are raw material: use them for structure and denominators, but fix conclusions and write to the vault only after the ledger (channels finish in ~20 min, the ledger in 40–90). Prices — from the `/pricing` page or schema.org markup; numbers from FAQs and comparison round-ups are secondary. Marketplace metrics (order counts, review ratios) are Tier C, not Tier B — they are purchasable.

**`QUERY_RU` / the report name must not contain characters Obsidian forbids in note names:** `: * " \ / < > | ?`. The 2026-08-22 plan set `QUERY_RU = "OM 5 + iPhone 17: падел"`; the workflow returned `queryRu: "Съёмка падела на OM 5"` and the file was written under the second name. Check `QUERY_RU` before launch and phrase without a colon («OM 5 + iPhone 17 — падел»); if the brief and the workflow disagree, take the Obsidian-valid one and note the deviation in the summary.

**Paired research on one topic — duplicate the hard constraints into both `decisionContext`.** 2026-08-18 (Prague / dozór): the second run, not knowing the first one's constraints, returned the verdict «go scout now», while the first had shown that leaving is legally forbidden until the measure is lifted in writing. Channels and the analyst see only their own `decisionContext`. Put 1–2 lines of the neighbour's hard constraints (restraining measure, runway, deadlines) into EACH paired run, even when the topic is about something else, and spell out in the second report's related-notes section how to read its verdict against the first. <!-- privacy-ok: «runway» как пример ограничения, не личные финансы -->

**The draft is `draft.md`, never `report.md` — CC blocks the name.** Since Claude Code 2.1.276 the Write tool refuses any subagent whose file basename matches `^(REPORT|SUMMARY|FINDINGS|ANALYSIS).*\.md$` (case-insensitive) with «Subagents should return findings as text, not write report files» (errorCode 5, before permissions, so no hook can allow it). On 2026-09-19 the analyst lost `report.md` in two runs and the report was recovered from its transcript. Fixed in 2.5.1 by renaming; `tests/test_workdir_names.py` keeps new workDir files out of that pattern — never name a subagent-written file report*/summary*/findings*/analysis*.md.

**Resolve-smoke of this skill needs `--tools Bash`.** The skill body carries a dynamic `` !`date +%Y-%m-%d` `` substitution, so `claude -p "/jadlis-research:research …" --tools ""` returns `result: ""` with 0 input / 0 output tokens — the headless harness refuses the preprocessing shell and no model call happens at all (bisected 2026-09-10: the same skill answers with 700+ tokens once the bang line is removed). The empty result looks like a broken plugin; it is not. Smoke with `--tools Bash --max-turns 1` so it stops after the first call.

**«full-research-core: …» thrown at launch — the args are broken, nothing ran.** Before 2.7.6 unparsable args (curly quotes „“ or a bare `"` inside a value), a `resumeFromRunId` call without args, or a missing key silently became the dry-run defaults and the whole pipeline ran on the test topic «Compare local AI coding assistants» (2–2.6M tokens per incident); a relative workDir scattered files under the session cwd. Since 2.7.6 the core throws before the first agent: the message names the missing keys or the JSON error with a 300-char preview of what arrived. Fix: rebuild the args from `{WORK_DIR}/_brief.md`, pass them in full (also on resume) with an absolute workDir; a deliberate test run needs `dryRun: true`.

**A channel came back LOW with 0 citations on a security-adjacent topic — check `classifierStops`, it may be a safety-classifier stop.** 2026-10-07 (`wf_0685606d-100`, «own Chrome for agents»): the cyber classifier stopped the web agent mid-Write; the agent stayed on Opus 5.5, wrote a stub and handed in a schema-valid `sourceQuality: LOW` with «the write-up was stopped partway through». The workflow took it for a weak channel and the summary said «Brave did not finish the report». The SubagentStop hook `refusal-no-fallback.py` caught the stop, but 9 s AFTER the StructuredOutput — a schema agent's marker never reaches `agent()`. Since 2.7.8 every schema role reports `interrupted`, the core re-runs a stopped role once on Opus 4.8 (`researcher-opus48` / `synth-opus48`, cap `classifierRetryCap`, default 6) and reports it in `classifierStops` and `channelStatus[].failReason: "classifier-blocked"`. Never re-run a stopped role by hand on Opus 5.5 — it stops the same way. Second check after a run: `python3 ~/.claude/scripts/refusal-audit.py "<Transcript dir>"`. Test the path without a real stop: `simulateClassifierStop: ["web"]`.
